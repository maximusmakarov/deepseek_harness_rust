# Shared host runtime (tier B/C-lite/C1/C2/C2.1-C2.7, rounds 78-103)

The Web UI serves one versioned, immutable module-table runtime to client-half
iframes so a half does not have to bundle its own copy
(`dsh.client.host_modules`). React/ReactDOM are the upstream production UMD
builds, unmodified; `bootstrap.js` is our glue that publishes the reference
module ids (including a jsx-runtime shim over `React.createElement`) in
`window.__DSHR_MODULES__`. `primitives.js` is the design-system shim, ported
in round 93 from the reference repository (`deepseek-ai/deepseek-harness @
39163dd`, `packages/client/ui-primitives/src`): the atoms follow the reference
DOM/props/ARIA/behaviour (`Button`, `Input`, `Switch`, `Checkbox`, `Tag`,
`Pill`, `SegmentedControl`, `SegmentedTabs`, `DisclosureRow`, `TextShimmer`,
`StateDot`, `PathLabel`, `Toast`, `Modal`, `Menu`, `MenuSurface`, `Tooltip`),
and all 204 reference `Icon*` exports are generated from the upstream
`icons/artwork.ts` artwork (inlined instead of the document sprite). Styling
uses the reference `--dsw-alias-*` tokens with fallbacks. The Tooltip placement engine, Menu core (rows/selection/keyboard), submenu
side-card/single-page layout, 200 ms hover grace, MenuGroup/observeStickyMenuGroups
and ShortcutKeys are ported. JsonBlock is a reference port. `markdown.js`
(round 103, C2.7) is the real upstream markdown stack, built from pinned npm
packages; it overrides `MarkdownText` in the primitives module entry (see
below), so the dependency-free GFM subset from round 97 is no longer served.
The submenu side-card/single-page decision, focus transitions and hover grace
follow the reference; `@deepseek-ai/dsh-client-store` (snapshot stores +
defineStore) is published in the module table for slot store seats.

## `markdown.js` — upstream markdown stack (C2.7, round 103)

`markdown.js` is generated by `scripts/build-markdown-runtime.mjs`; do not edit
it by hand. The build installs the pinned npm tree into
`target/markdown-runtime` (gitignored, network needed only on the first run),
bundles `@deepseek-ai/dsh-client-ui-primitives@0.0.1-rc.1`'s `MarkdownText`
with esbuild as a classic-script IIFE (no ESM import, no `eval`) and
re-publishes it on `@deepseek-ai/dsh-client-ui-primitives`, keeping every other
export of the port (`Spinner`, `useAnchoredPosition`, icons, …). The renderer is
the reference one: micromark/mdast with GFM (tables, task lists,
strikethrough, autolinks, footnotes) and math (`$…$`, `$$…$$` through KaTeX
0.16.47), the reference incremental streaming parser (frozen blocks + trailing
tail reparse), and shiki 4.3.1 core with the JavaScript regex engine and the
boot grammars TypeScript, shellscript and JSON. The reference's lazy read-card
grammars are stubbed to empty registrations so ~1.6 MB of never-used grammars
stay out of the artifact; such fences render as plain code. React, ReactDOM and
`react/jsx-runtime` are build-time externals aliased to `react.cjs`,
`react-dom.cjs` and `jsx-runtime.cjs` shims over `window.React`,
`window.ReactDOM` and `window.__DSHR_MODULES__["react/jsx-runtime"]` — the
artifact contains no second React.

The wrapper keeps the dshr prop surface (`text`, `streaming`, `codeLabels`,
`fileMentions` plus the port's `labels`/`variant`/`className`/
`textInteractionSource`) and restores the port's `.dshr-markdown` styling hooks
on an outer div. `JsonBlock` stays the reference port from `primitives.js`: its
DOM/behaviour matches the upstream component and it keeps the stable
`.dshr-json-block-*` classes; the upstream `JsonBlock` is therefore not
re-published. `markdown.js` also installs the KaTeX layout sheet (with
`@font-face` stripped — the artifact carries no font files, so math uses the
document's fallback glyphs) and a zero-specificity shiki `--shiki-*` fallback
palette (`:where(html)`, so a real theme sheet always wins).

Rebuild: `node scripts/build-markdown-runtime.mjs` (also refreshes
`checksums.txt`); `node scripts/build-markdown-runtime.mjs --check` verifies
that the committed bytes match a fresh build.
