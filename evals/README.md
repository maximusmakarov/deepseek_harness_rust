# Eval-набор `dshr` (ROADMAP 2.12)

Десять детерминированных задач, которые проверяют не только «агент ответил», но и
фактический результат: вызван нужный инструмент, файл создан/изменён, журнал
консистентен. Модель не вызывается: ответы проигрываются из кассеты, поэтому
набор работает офлайн и в CI.

## Как устроена задача

`evals/tasks/NN-*.json`:

| Поле | Смысл |
|---|---|
| `id`, `title` | Идентификатор и человекочитаемое имя |
| `prompt` | Запрос пользователя (позиционный аргумент `dshr run`) |
| `files` | Файлы, создаваемые в чистом временном workspace до запуска |
| `calls` | Кассета: по одному элементу на каждый запрос к модели (`start` → `tool_use_start` / `text_delta` → `usage` → `done`) |
| `expect.stdout_contains` | Подстроки, обязанные быть в итоговом тексте ответа |
| `expect.files_contain` | Файлы и подстроки, которые обязаны появиться после прогона |
| `expect.files_absent` | Файлы, которых быть не должно |
| `expect.steps_max` / `tool_calls_max` | Жёсткие лимиты шагов агента и вызовов инструментов |
| `expect.tokens_max` | Бюджет «стоимости» задачи (usage из кассеты) |

## Метрики

На каждый прогон пишется `target/evals/report.json` (путь можно переопределить
через `DSHR_EVAL_REPORT`): по задаче — `ok`, `steps`, `tool_calls`, `tokens`,
`elapsed_ms`, причины падения; в `summary` — success rate, суммарные токены и
время. Гейт: **success rate = 100 %**, превышение лимитов шагов/токенов — падение
теста.

## Запуск

```bash
cargo test -p dshr-cli --test evals -- --nocapture
```

Добавление задачи — новый JSON-файл; менять код не нужно. `calls` можно записать
вручную или получить через `dshr run --record <file>`, затем вырезать из него
лишние вызовы.

## Покрытие

read, grep, glob, write, edit, apply_patch, bash, todo, subagent, многошаговый
цикл read → edit → bash. Это десять самых частых сценариев harness; каждая задача
несёт собственный бюджет токенов, поэтому рост «стоимости» ловится как регресс.
