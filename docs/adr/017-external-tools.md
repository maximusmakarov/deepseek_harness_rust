# 017. MCP, web, jobs и субагенты: границы M4

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

M4 добавляет внешние инструменты и делегирование. Нужно определить, что входит в ядро, а что сознательно откладывается, чтобы не тащить в M4 HTTP-транспорты, durable-очереди и бюджеты.

## Решение

1. **MCP — stdio-подмножество.** Реализованы `initialize`, `notifications/initialized`, `tools/list`, `tools/call`; инструменты получают имя `mcp__<server>__<tool>`. Сервер, который не поднялся, логируется и пропускается — harness продолжает работу. HTTP-транспорт, resources, prompts и sampling отложены.
2. **Web.** `web_fetch` — только http/https, ручные редиректы (до 3) с повторной проверкой, блокировка private/loopback/link-local, лимит 5 МБ, HTML→текст. `web_search` — Brave Search API по `BRAVE_SEARCH_API_KEY`; без ключа инструмент возвращает понятную ошибку.
3. **Jobs.** Процессы живут в текущем harness-процессе, вывод хвостовой (64 КБ), статус и kill через `job_*`. Durable jobs и переживание рестарта отложены.
4. **Субагенты.** Дочерний агент получает новую сессию, того же провайдера, политику и набор инструментов **без** `subagent` — глубина ограничена единицей по построению. Бюджеты токенов/времени на дерево отложены.

## Последствия

- Внешние инструменты не блокируют старт: частичная доступность лучше отказа.
- Сеть и MCP-серверы недоверенные: SSRF-фильтр, таймауты, лимиты вывода.
- M4 закрывает сценарии «браузер/поиск/фон/делегирование», но не является полноценным MCP-хостом.
- Дочерние сессии видны в `sessions list` и поиске; родитель получает только финальный текст.

## Альтернативы

- Полный MCP SDK с HTTP и sampling сразу — отклонено: объём и нестабильность транспорта.
- Durable jobs на SQLite — отложено до появления реальных фоновых сценариев.
- Рекурсивные субагенты без бюджета — отклонено: риск бесконечного дерева и расходов.
