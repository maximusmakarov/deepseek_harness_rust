# 034. ACP v1 server

- **Статус:** Accepted
- **Дата:** 2026-11-13

## Контекст

Редакторы (Zed и др.) интегрируют агентов через Agent Client Protocol. Нужен stdio JSON-RPC сервер с сессиями и стримом, но без полного набора клиентских capability.

## Решение

1. **ACP v1 over stdio:** `initialize`, `session/new`, `session/prompt`, `session/cancel`.
2. **Стрим:** `session/update` с `agent_message_chunk`, `tool_call`, `tool_call_update`.
3. **Turn в фоне:** prompt запускается задачей, поэтому cancel-уведомление обрабатывается во время выполнения; один активный turn на сессию.
4. **Approvals:** `session/request_permission` к клиенту; `allow-once`/`reject-once`, таймаут 300 с; `--danger` отключает запросы.
5. **Файлы:** `fs/read_text_file`/`write_text_file` при client capability; локальный fallback иначе.
6. **Терминал:** `terminal/create`/`wait_for_exit`/`output`/`release` при `clientCapabilities.terminal`.
7. **Сессии:** `session/load` с replay, `session/resume` без replay, `session/close`.
8. **Границы:** нет image/audio и клиентских MCP-серверов.

## Последствия

- Редактор получает текст, tool-события и запросы разрешений.
- ACP-клиент не управляет файлами/терминалом — инструменты harness работают локально.
- Изображения — следующий срез.

## Альтернативы

- ACP SDK — отложено: минимальный протокол проще и достаточно для текстовых сессий.
- Отдельный HTTP-транспорт — отклонено: ACP рассчитан на stdio.
