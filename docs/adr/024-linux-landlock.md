# 024. Linux Landlock: helper и границы изоляции

- **Статус:** Accepted
- **Дата:** 2026-11-13

## Контекст

После M5 Linux оставался fail-closed: `bash` и jobs отказывали, потому что не было бэкенда. Это ломало основной сценарий на Linux/CI и делало автономные расписания с shell бесполезными.

## Решение

1. **Landlock через helper-процесс.** Бэкенд подменяет команду на сам бинарь `dshr` с скрытым аргументом `__sandbox-exec`; helper применяет ruleset и делает `exec` целевой команды. Это избегает `unsafe` `pre_exec` и работает с одним бинарём.
2. **Правила (ABI V1):** чтение/исполнение `/`; для `workspace-write` — запись в workspace, `temp_dir` и `/dev/null`. `read-only` не даёт записи, кроме `/dev/null`.
3. **Fail-closed:** если Landlock не enforced, helper завершается с кодом 125 и команда не выполняется.
4. **Сеть не ограничивается:** Landlock ABI V1 покрывает только файловые эффекты, поэтому enforcement помечен `Partial`. Это документируется, а не маскируется.
5. **Windows** остаётся fail-closed; ACL/Job Objects — отдельный срез.

## Последствия

- Shell и jobs на Linux работают в ограниченном workspace; escape-тесты проверяют запись вне workspace и успешную запись внутри.
- Один бинарь: helper не нужно устанавливать отдельно.
- Сетевые ограничения на Linux пока отсутствуют; для них нужен seccomp/network-слой.

## Альтернативы

- `pre_exec` с `landlock` в дочернем процессе — отклонено: `unsafe` в кодовой базе.
- Отдельный бинарь `dshr-sandbox-exec` — отклонено: ломает single-binary поставку.
- `bwrap` — отклонено: внешняя зависимость, часто недоступна в CI.
