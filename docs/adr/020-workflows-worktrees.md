# 020. Workflows и worktrees: первый срез M7

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

M7 — это паритет по десятку подсистем. Начинать с самой дорогой (LSP/Office/CUA/desktop) нерационально; нужен срез, который сразу усиливает агентные сценарии и проверяется без внешних сервисов.

## Решение

1. **Workflows** (`dshr-workflow`): YAML-файл с DAG шагов, `depends_on`, шаблоны `{{input}}` и `{{step_id.output}}`. Шаги выполняются последовательно в топологическом порядке; каждый шаг — отдельная сессия субагента. Циклы, дубликаты id и неизвестные зависимости отклоняются при загрузке.
2. **Изоляция рекурсии:** `workflow` и `subagent` регистрируются только в родительском реестре; дочерний агент их не видит.
3. **Worktrees**: `worktree_create/list/remove` создают git-worktree под `.dshr/worktrees`, удаление разрешено только внутри этого каталога.
4. **Границы среза:** параллельные шаги, retries, расписания и agent teams не входят; worktrees не автоматизируют merge/PR.

## Последствия

- Мультиагентные сценарии доступны без внешних сервисов и проверяются кассетами.
- Workflow-файлы — пользовательские артефакты; их формат версионируется через ADR.
- Worktrees требуют git и работают в пределах workspace; на Windows путь проверяется тем же `starts_with`.

## Альтернативы

- Workflows на Rhai/Lua — отложено: YAML-DAG покрывает типовые цепочки.
- Параллельное исполнение шагов — отложено до появления бюджетирования субагентов.
- Начинать M7 с LSP/Office/CUA — отклонено: высокая цена, слабая проверяемость без внешних зависимостей.
