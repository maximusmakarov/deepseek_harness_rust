# 018. Песочница и плагины: границы M5

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

M5 должен ограничить процессы и дать расширяемость. Полный паритет (Seatbelt + Landlock + seccomp + ACL, WASM-компоненты, hot reload) — это несколько недель; нужно определить исполнимый срез.

## Решение

1. **Политика песочницы** (`dshr-sandbox`): `read-only`, `workspace-write`, `danger-full-access`; сеть по умолчанию запрещена; политика применяется к `bash` и фоновым jobs.
2. **macOS Seatbelt** реализован полностью: профиль генерируется из политики, запись разрешена только в workspace/temp, сеть запрещена. Escape-тест проверяет запись вне workspace.
3. **Linux/Windows** пока используют `UnsupportedBackend`: в confined-режиме команда не выполняется (fail-closed), а не деградирует до неограниченной. Landlock/seccomp/ACL — следующий срез.
4. **Плагины** на M5 — это управление MCP-коннекторами: `dshr plugin add/list/remove` пишет `mcp.servers` в пользовательский конфиг; композиция профилей/слоёв уже есть.
5. **WASM/sidecar/hot reload/capability audit** отложены: для них нужен отдельный ABI и модель доверия; MCP закрывает большинство внешних инструментов.

## Последствия

- На macOS sandbox реально ограничивает shell; на других ОС — честный отказ вместо ложной безопасности.
- Плагинная экосистема пока ограничена MCP; WASM-тир не заявлен как готовый.
- `--danger` — единственный способ обойти confinement; это явное действие пользователя.

## Альтернативы

- Сразу Landlock/seccomp/ACL — отложено: разные ядра и CI-раннеры, высокий риск ложных падений.
- WASM на wasmtime с component model — отложено: тяжёлая зависимость и отдельный ABI.
- Не делать песочницу до T3 — отклонено: shell уже доступен агенту.
