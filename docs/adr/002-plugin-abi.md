# 002. ABI плагинов: WASM + sidecar

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

Cordis-плагины — TS в общем процессе; в Rust нужен безопасный и переносимый ABI.

## Решение

Компоненты WASM (wasmtime, WIT) с capability-grants; sidecar по JSON-RPC для языков вне WASM; MCP для внешних серверов. `libloading` не используем.

## Последствия

Изоляция, лимиты, языковая нейтральность; сам WASM-тир не даёт совместимости с npm/Cordis — её обеспечивает отдельный Cordis-рантайм ([ADR-013](013-cordis-compat.md)).

> **Уточнение (2026-11-12, по [ARCHITECTURE §13.4](../ARCHITECTURE.md#134-соседние-проекты-что-перенимаем)):** из production-практики принято — единственный диспетчерский host-импорт `call(op, payload)` вместо набора импортов; кэш грантов с аудитом для всех плагинов, включая встроенные; `api_version` в манифесте, матрица совместимости и SDK-крейт с semver; сменный рантайм-бэкенд (wasmtime по умолчанию, wasmi как опция); `oci://`-адресация артефактов. Не принято: наследование env в WASI, protobuf поверх пайпов, загрузка только на старте, дистрибуция через Git и собственный ABI с trampoline. Адаптеры чужих ABI (proxy-wasm / http-wasm / Extism) — через шов `host_api`, решение отложено до спроса.

## Альтернативы

- Оставить как в DSH Desktop — отклонено: другой рантайм и/или несовместимый ABI.
- Отложить решение — отклонено: блокирует M0/M1.
