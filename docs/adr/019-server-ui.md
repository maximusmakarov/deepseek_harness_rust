# 019. Сервер, Web UI и SDK: границы M6

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

M6 должен дать удалённый доступ к агенту и браузерный интерфейс. Полный набор (WS, OpenAPI, Leptos, SDK на нескольких языках, cargo-dist) — это отдельный фронтенд/релизный проект.

## Решение

1. **HTTP/SSE на axum.** REST для сессий и turn'ов, SSE для событий (`text`, `tool_*`, `approval`, `done`, `error`). WebSocket не добавляется: SSE закрывает стрим в одну сторону, а действия идут обычными POST.
2. **Аутентификация** — bearer-токен; для `EventSource` разрешён `?token=`, потому что браузерный API не даёт задать заголовок.
3. **Approvals по API:** turn приостанавливается на `oneshot`, сервер отдаёт `approval`-событие с id, `POST .../approvals/{id}` разрешает или запрещает.
4. **Web UI — встроенный vanilla JS** без сборки: сессии, чат, стрим, tool-карточки, approvals. Leptos-версия отложена: для M6 важнее рабочий e2e-контур, чем стек.
5. **SDK** — JSON-RPC-подмножество (`session.list/get/create`) на `/v1/rpc`; полноценные клиенты и остальные методы отложены.
6. **Упаковка** — Dockerfile; cargo-dist/brew и подпись отложены.

## Последствия

- Один бинарь отдаёт API и UI; CORS открыт для локальной разработки.
- Нет rate-limit и OpenAPI-контракта — это следующий срез.
- Браузерный e2e (Playwright) не входит в CI; HTTP/SSE проверяются интеграционными тестами.

## Альтернативы

- WebSocket — отложено: SSE + POST проще и достаточен.
- Leptos сразу — отложено: тяжёлый фронтенд-проект.
- SDK на Python/TS в M6 — отложено: сначала стабильный HTTP-контракт.
