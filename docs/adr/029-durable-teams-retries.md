# 029. Durable teams и retries workflow

- **Статус:** Accepted
- **Дата:** 2026-11-13

## Контекст

Доска agent teams жила в памяти: падение процесса теряло прогресс. Workflow-шаги падали с первой ошибкой, хотя transient-сбои типичны для сетевых/инструментальных вызовов.

## Решение

1. **Durable board:** состояние команды пишется в `.dshr/teams/<name>.state.json` после каждого claim/complete/fail. Запись сериализуется мьютексом, чтобы фоновые воркеры не перезаписывали более новое состояние старым снимком.
2. **Resume:** `team` принимает `resume: true`; состояние загружается, `in_progress` задачи возвращаются в `pending` (владелец потерян), `done` сохраняются. Без `resume` создаётся новая доска.
3. **Workflow retries:** у шага есть `retries` (0–10). Шаг повторяется при ошибке; после исчерпания ошибка содержит число попыток.
4. **Границы:** состояние команды — снимок, а не журнал событий; durable workflow-состояния нет; backoff/джиттера нет.

## Последствия

- Прерванный team-run можно продолжить, не выполняя завершённые задачи повторно.
- Ошибки шага workflow переживают transient-сбои без внешнего оркестратора.
- Запись state-файла не транзакционна относительно kill -9; последний снимок может отставать, но не теряет завершённые задачи.

## Альтернативы

- Event-sourced доска в SQLite — отложено: снимок достаточен для M7.
- Retry с exponential backoff — отложено: нет таймингов/DLQ.
- Durable workflow — отложено: сначала teams.
