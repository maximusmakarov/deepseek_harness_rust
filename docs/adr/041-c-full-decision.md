# 041. C-full: решение по полной React-совместимости

- **Статус:** Accepted (частично): C-lite/C1/C1.1/C2 закрыты, C-full отложен как отдельная фаза
- **Дата:** 15.11.2026
- **Связанные:** [013](013-cordis-compat.md) §5–6, [040](040-react-client-half.md)

## Контекст

[ADR-040](040-react-client-half.md) оставил открытым тир **C-full**: полный
design-system `@deepseek-ai/dsh-client-ui-*`, SlotMap-семантика
(`ownerProps`/framework-hooks/cardinality/scope/chain/hoc), React-контекст и
состояние шелла, композиция между плагинами, host-сервисы
`pluginManager`/`settings` и streaming. После раундов 79–87 реализованы
C-lite, C1, C1.1 и C2, и накопились фактические данные о том, где проходит
граница «просто» и «дорого».

## Что уже работает (факты, а не оценки)

| Слой | Состояние | Доказательство |
|---|---|---|
| React-компоненты слотов | да: `ctx.slots.register(entry, Component)`, memo/forwardRef, keyed, error boundary | bridge harness 87, smoke |
| host-state/hooks | `theme`/`wide`/`session`/`sessions`, `useTheme`/`useSession`/`useSessions`/`useHostState`, `ctx.get('sessions')` | C-lite |
| design-system шим | 30+ экспортов (компоненты/иконки+Proxy/hooks/clipboard) по реальным импортам | C2, 176 725 байт рантайма |
| host HTTP-маршруты | да: loopback sidecar + allowlist proxy, exact/prefix, CORS, лимиты, статус, фильтр MCP-мусора, loopback-only LAN | C1 + хардненинг |
| сервисы sessions/projections | да, снимком (≤5 с задержка, упрощённая проекция) | C1.1 |
| conformance | **n=11** реальных MIT-плагинов (цель 8–12 достигнута) | smoke 80/80 на момент решения |

## Что осталось в C-full и почему это отдельная фаза

1. **Полный design-system** (`@deepseek-ai/dsh-client-ui-*`): точные визуальные
   токены, compound-компоненты, темы/анимации. Это не «ещё N функций», а
   воспроизведение закрытого UI-пакета: нужен либо официальный пакет, либо
   многократный рост шима вширь (каждый компонент — отдельная семантика).
2. **SlotMap-семантика**: `ownerProps`, cardinality/scope/chain/hoc,
   framework-hooks (chat/composer/queue). Требует реверс-инжиниринга
   контракта DSH-слотов по реальным плагинам: пока таких плагинов в наборе
   мало, а спецификация не публична. Прогноз: 2–4 недели только на PoC одного
   семейства слотов + риск неверной семантики.
3. **React-контекст/состояние шелла**: сейчас шелл — Leptos; проброс React
   Context из DSH-шелла невозможен без React-шелла. Практический путь —
   собственный React-провайдер с референсным API (theme/session/slots), то есть
   подмножество без гарантии паритета.
4. **Host-сервисы `pluginManager`/`settings`**: нужны для UI реальных плагинов
   управления плагинами (conformance `dsh-plugin-debugging`/`dsh-plugin-studio`
   активируются, но их панели не монтируются). Достижимо через тот же
   bridge-механизм, что C1.1, но требует спроектировать API этих сервисов.
5. **Streaming/SSE/WebSocket** через plugin-маршруты: нужен стриминговый прокси;
   пока точных плагинов-потребителей в наборе нет.

## Решение

1. **C-full не делаем сейчас** целиком. Останавливаемся на текущем объёме:
   C-lite + C1 + C1.1 + C2 закрывают «экосистема работает для простых
   UI-плагинов» и «реальные плагины получают данные».
2. Дальнейшие шаги — **по спросу и точечно**, каждый как отдельный инкремент:
   - host-сервисы `pluginManager`/`settings` (самый дешёвый и заметный
     следующий шаг: закрывает 2 плагина набора);
   - SlotMap PoC одного семейства слотов (например, `conversation.*`), если
     появится реальный плагин, которому нужны ownerProps;
   - streaming-прокси — только при появлении плагина, который без него не
     работает;
   - полный design-system — только при появлении официального пакета/лицензии
     или требования визуального паритета.
3. **Критерий возврата к C-full:** ≥3 реальных плагина набора перестают
   работать из-за отсутствия пунктов 1–5 (сейчас таких нет: все 11 либо
   работают, либо деградируют штатно).

## Последствия

- ADR-040 остаётся **Proposed** в части C-full; реализованные тиры (B-PoC,
  C-lite, C1, C1.1, C2) считаются принятыми и зафиксированы в нём.
- Техдолг «C-full» в TECH-DEBT остаётся Deferred с ссылкой на этот ADR и
  списком точечных кандидатов.
- Никакого обещания полной совместимости с DSH UI-плагинами: документированный
  объём — 11 плагинов conformance и перечисленные возможности.
