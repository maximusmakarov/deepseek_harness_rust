# 013. Совместимость с npm/Cordis плагинами рядом с WASM

- **Статус:** Accepted; sidecar-прототип 13.11.2026, hot reload и мост клиентской половины 14.11.2026; подтверждён владельцем 2026-11-12 (режимы по умолчанию: `cordis-sidecar`, мост UI в T3, `postinstall` выключен)
- **Дата:** 2026-11-12
- **Уточняет:** [ADR-002](002-plugin-abi.md) (его вывод «не совместимо с Cordis/npm» отменён; WASM-тир и sidecar остаются)
- **Влияет на:** ARCHITECTURE §13, PLAN §3.2/§5, ROADMAP M5b, IMPROVEMENTS §2.3/§5, LIMITATIONS §2.4

## Контекст

Требование: **поддержка npm/Cordis-плагинов DSH сохраняется**, а новая система плагинов на WASM добавляется — и при этом пользователь не теряет сильные стороны Cordis/npm. Прежняя редакция плана ([ADR-002](002-plugin-abi.md), ARCHITECTURE §13.5) явно отказывалась от совместимости, поэтому решение пересматривается.

Что такое плагин DSH (проверено по установленному `0.2.2-rc.2`):

- **Host-половина** — npm-пакет, экспортирующий Cordis-плагин (`apply(ctx, config)` / класс / функция), смонтированный строкой Loader'а в `cordis.patch.yml` профиля. Код исполняется в общем процессе Node с полным доступом к `fs`, `net`, `child_process`, `process.env` и любым npm-зависимостям.
- **Client-половина** — объявление `dsh.client` в `package.json` (платформа `web`) и собранный бандл в `exports["./client"]`; браузерный Cordis Loader собирает их в ленивую CJS-таблицу модулей, UI-слоты рендерятся React'ом.
- **Сильные стороны**, которые надо сохранить: экосистема npm, HMR и быстрый цикл правки, богатый объектный API `ctx.*` (сервисы, события, waterfall-хуки, fiber-жизненный цикл), клиентские UI-расширения, TypeScript-типы.

Фундаментальное ограничение: эти свойства — свойства **JS-семантики**. Их нельзя «портировать» в WASM: объектный граф `ctx`, `await` в хуках, ESM/CJS-резолвинг, React/DOM — всё это требует JS-движка. Значит совместимость и WASM-тир должны сосуществовать как **разные рантаймы под общим контрактом**, а не как один универсальный формат.

## Решение

### 1. Один шов — четыре рантайма

`dshr-plugin` реализует трейт `PluginRuntime` и единый жизненный цикл (manifest → validate → resolve capabilities → instantiate → health-check → activate → replace/rollback → stop). Рантаймы:

| Рантайм | Что это | Доверие | Кому |
|---|---|---|---|
| `native` | Крейт + регистрация в композиции | полное | встроенные инструменты, провайдеры |
| `wasm` | Компонент wasmtime + WIT + capability-grants | ограниченное | сторонние инструменты/хуки без пересборки |
| `cordis` | JS-рантайм: настоящий `cordis` + настоящие npm-пакеты | как в DSH, но через capability-шину | существующие плагины DSH, TS-разработка |
| `external` | Sidecar по JSON-RPC / MCP | процесс в песочнице | чужие серверы, языки вне WASM |

Все рантаймы дают вклад в **один** реестр (инструменты, хуки, команды, слоты UI) и пишут в **один** аудит. Плагин одного рантайма может вызывать инструмент другого — только через host-посредник, без прямой линковки.

### 2. Cordis-рантайм: исполнять, а не эмулировать

`cordis` — небольшой MIT-пакет. Мы **запускаем его как есть** (вендорим версию), а не переписываем его API на Rust: переписывание дало бы вечный дрейф и всё равно не запустило бы реальные пакеты.

Два исполнения, выбираются профилем:

- **`cordis-sidecar` — рекомендуется первой.** `dshr` поднимает собственный процесс-рантайм (runtime pack: вендоренный Node-совместимый движок либо системный Node, если найден), внутри — настоящий `cordis` и настоящие npm-пакеты. Общение с host'ом — тот же JSON-RPC, что у sidecar-плагинов; процесс живёт в песочнице. Семантика совпадает точно, работы по ABI — ноль.
- **`cordis-embedded` — опция позже.** `deno_core`-подход (V8 + node-compat шимы) в отдельном потоке/изоляте. Сохраняет «один бинарь», но добавляет порядка десятков МБ и время инициализации.

Базовый бинарь при этом остаётся маленьким: runtime pack — отдельный артефакт с хешем и подписью, ставится по требованию (`dshr runtime install cordis`) и только тогда, когда в профиле есть JS-плагины.

### 3. Node-builtins → capabilities (и это строго безопаснее DSH)

Тот же код плагина, но системные вызовы проходят через наши швы:

| Builtin | Как обслуживается |
|---|---|
| `path`, `url`, `events`, `util`, `buffer`, `string_decoder` | чистый JS (исходники Node, MIT) — настоящая семантика, привилегий не требует |
| `fs`, `fs/promises` | host `ctx.fs`: sandbox-политика, удержание в workspace, read-before-edit, аудит; `fs.watch` → host-события |
| `child_process` | exec-шов: approvals + песочница; argc/argv вне политики → типизированный отказ |
| `net`, `http(s)`, `dgram` | deny by default; allow-list через capability-grant |
| `process` | отфильтрованное окружение (редакция секретов), без `dlopen`/`binding`; `process.exit` останавливает плагин, не host |
| `crypto` | RNG и ключи остаются на host'е |
| прочее | `DSH_COMPAT_UNSUPPORTED` — явная диагностика, без тихой деградации |

Итог: непортированный плагин DSH запускается, но его `fs`/`net`/`exec` **видны и ограничены** — это надмножество безопасности DSH при неизменном коде плагина.

### 4. Поверхность `ctx` — контракт `dshr:cordis-compat@1`

Шим-пакет `@dshr/cordis-compat` реализует сервисы DSH поверх host-RPC: `tools`, `fs`, `shell`, `llm` (стрим), `session`/лог, `settings`, `storage`, `commands`, `approval`/`userQuestions`, `subagents`, `jobs`, `skills`, `mcp`, `web`. Схемы конфигурации (`Config`) поддерживаются в объёме, нужном плагинам; неподдержанное — в матрице совместимости.

Совместимость привязана к API DSH `0.2.x`, а не к его поведению: целимся в «плагин загружается и делает свою работу», а не в побайтовый паритет промптов и эвристик.

### 5. Client-половина: мост, а не React-совместимость

ADR-003 фиксирует Leptos для Web UI, а клиентские плагины DSH — React. Переписывать шелл на React мы не будем, поэтому:

- UI плагина рендерится в **изолированном iframe** (или отдельной странице-острове) и общается с шеллом типизированным `postMessage`-мостом;
- мост реализует подмножество слотов DSH на нашем реестре слотов: панель, действие у сообщения, секция настроек, команда;
- произвольная инъекция в DOM шелла и полный набор React-слотов — **вне scope**.

Это сохраняет Leptos-архитектуру и попутно даёт изоляцию UI-плагина.

### 6. Дистрибуция и воспроизводимость (оба тира)

- npm-тарболы тянутся через content-addressed store с lock-файлом и проверкой подписи; транзитивные зависимости резолвит собственный npm-совместимый резолвер, а не pnpm.
- Lifecycle-скрипты пакетов (`postinstall` и прочие) по умолчанию **не исполняются**: включаются явным флагом установки, и это событие попадает в аудит — иначе CAS и подписи теряют смысл.
- WASM/OCI-артефакты — по тем же правилам (хеш, подпись, откат версии, офлайн-зеркало).
- Conformance-набор: 8–12 реальных плагинов DSH из npm, прогон в CI (nightly) на матрице «загрузился / инструменты вызвались / хуки сработали».

## Последствия

**Плюсы**

- Экосистема, HMR и DX npm/Cordis сохраняются; WASM даёт изоляцию для недоверенного и переносимого кода.
- Один реестр и один аудит для всех тиров → инструменты взаимозаменяемы, UI «Плагины» один.
- Безопасность лучше референса: capability-опосредованные builtins и аудит там, где у DSH полный доступ.

**Минусы и цена**

- Runtime pack — новая сущность: загрузка, проверка хеша, версия, офлайн-режим.
- Два движка = две поверхности багов; дрейф Cordis/Node API и CVE V8/Node нужно отслеживать.
- Client-половина совместима на уровне моста: часть UI-плагинов DSH не заработает без адаптации.
- Оценка: `cordis-sidecar` — 12–18 ИД; `cordis-embedded` — +10–15 ИД; мост UI — 8–12 ИД (T3).
- Метрика «один статический бинарь ≤ 80 МБ» остаётся для базовой поставки; при включённом embedded-рантайме бюджет пересматривается (≤ 130 МБ).

## Альтернативы

- **Только WASM (прежний ADR-002).** Отклонено требованием: теряется экосистема и DX, которые и просили сохранить.
- **Только Cordis-совместимость, без WASM.** Отклонено: недоверенный код остаётся с полными правами, нет переносимого артефакта.
- **Переписать Cordis API на Rust (без JS-движка).** Отклонено: это объектный граф на JS; реализация = постоянный дрейф и несовместимость с реальными пакетами.
- **Нативные `.so`/`.dylib`.** Отклонено: нестабильный ABI, нулевая изоляция.
- **Client-половина на React-острове с полной совместимостью слотов.** Отложено: цена сопоставима с отдельным фронтенд-проектом и противоречит ADR-003.

## Реализация (13.11.2026)

`dshr-cordis`: JS-плагин запускается отдельным `node`-процессом, bootstrap публикует `ctx.tool` через MCP stdio; при наличии пакета `cordis` используется настоящий `Context.plugin`. Capability-шина минимальная (`ctx.fs` в workspace + гранты, `exec`/`net` запрещены), без кэша грантов. Это вертикальный срез, а не полный 12–18-дневный объём ADR.

## Реализация hot reload и клиентской половины (14.11.2026)

**Живой набор плагинов.** `ToolRegistry` стал общим handle'ом (`Arc<RwLock<…>>` + счётчик генераций, `register`/`unregister`/`remove_prefix`/`register_all` по `&self`), поэтому реестр можно менять под работающим агент-циклом: сессии держат тот же handle и видят новую генерацию инструментов со следующего вызова. `dshr_cordis::CordisManager` владеет sidecar-процессами: `start`/`stop`/`reload`/`sync`, генерация на запуск, статус с ошибкой последней попытки, broadcast событий жизненного цикла. Остановка снимает ровно инструменты плагина и роняет backend (`kill_on_drop`) после завершения in-flight вызовов; перезагрузка — новый процесс, состояние плагина сбрасывается.

**Триггеры.** Поллинг-watcher (750 мс) в `dshr serve`: штампы mtime/размера по каталогу пакета (без `node_modules`/`.git`/`target`) и по `profile.yaml`/`config.yaml`; изменение конфига вызывает `sync`, то есть `plugin npm add/remove/enable/disable` применяются без рестарта. Плюс `POST /v1/plugins/reload` (`{name}` или все) для UI и скриптов. Отключается `--no-watch-plugins`. Фильтр `tools.allowed`/`denied` применяется и к динамическим регистрациям, иначе плагин обходил бы allowlist.

**Клиентская половина** следует §5 этого ADR: React-совместимости нет, есть мост.
- `dsh.client` (`platform: "web"`, `entry` или `exports["./client"]`) обнаруживается в каталоге пакета; путь канонизируется и обязан оставаться внутри пакета.
- Host-страница (`GET /v1/plugins/{name}/host`) исполняется в `<iframe sandbox="allow-scripts">`: origin непрозрачный, CSP `default-src 'none'` запрещает сеть, бандл встроен base64 и импортируется из blob-URL — токен и запросы не покидают шелл. `client.js` остаётся отдельным маршрутом для отладки.
- Мост `window.dshr` (протокол v1): `slots.register/remove/list`, `action(action,payload)`, `theme`, `log`; сообщения размечены `ns`/`v`. Шелл активирует слот, отвечает на `action` (`close`, `reload`) и показывает ошибки плагина.
- Web UI: панель Plugins показывает клиентские половины, их live-статус, кнопку Reload; панель открывается в sandboxed iframe, deep link `?token=…&plugin=…`.

**Что осталось от объёма ADR:** полный набор React-слотов и произвольная инъекция в DOM (сознательно вне scope), кэш грантов и conformance-набор из 8–12 реальных плагинов, `cordis-embedded`.

## Углубление клиентской половины (14.11.2026, раунды 64–66)

Срез доведён от «одного слота» до рабочей модели DSH-половины, насколько это
позволяет мост без React:

- **Слоты.** Регистрация принимает референсную форму `{name, id, title, order}` и
  `ctx.slots.inject(ownerKey, factory)`; шелл строит вкладки по слотам (порядок
  `order`), переключает `activate`, закрывает `deactivate` без потери регистраций.
- **Жизненный цикл.** `ctx.effect` и группы `inject` снимаются на `dispose` и
  выгрузке кадра; `immediately`-половины монтируются скрыто при старте в порядке
  `inject`, поэтому их фоновые эффекты живут, пока открыт шелл.
- **Доставка.** Один файл — inline base64 с сетевым запретом в CSP. Многофайловый
  бандл (обнаруживается по относительным `import`/`require` или
  `dsh.client.bundle: "assets"`) грузится с capability-адреса
  `/v1/plugins/{name}/asset/{capability}/…` (TTL 1 час, confined к пакету), CSP
  разрешает только origin сервера; токен в кадр не попадает.
- **Хост-действия.** `ctx.action` выполняет `close`, `reload`, `compose`
  (вставка в промпт), `notify` (статус-строка); результат возвращается плагину.
- **Перезагрузка.** После reload супервизора шелл поднимает версию кадра, и
  открытая панель подхватывает новый бандл без переоткрытия.
- **Проверка.** Node-харнесс моста в `cargo test`, серверные тесты capability-режима
  и `scripts/plugin-smoke.py` — 28 проверок в headless Chrome (слоты, resize,
  тема, действия, eager-кадр, многофайловый и module-table бандлы, hot reload).
  Оценка Replica `replica-diff` по клиентской половине: **98.0/100, must 12/12**
  (`docs/replica/client-half-parity.md`).

Осталось: React-совместимость и общий стол модулей (вне scope §5), conformance-набор
реальных пакетов, `dsh.client.external`.
