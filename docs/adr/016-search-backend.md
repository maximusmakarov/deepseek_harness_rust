# 016. Поиск по сессиям: скан сейчас, индекс по гейту

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

M3 добавил `sessions search` линейным проходом по JSONL. Обсуждался SQLite FTS5 как «очевидный» следующий шаг. Для локального harness это неочевидно: запросы — код и идентификаторы, корпус — сотни-тысячи сессий, а поставка — один бинарь на трёх ОС.

## Решение

1. **По умолчанию — скан.** Источник истины — JSONL; поиск не требует перестройки индекса и всегда консистентен.
2. **Сначала оптимизировать скан**, а не индексировать: искать по сырым строкам без полной десериализации, `memchr`/`aho-corasick`, без `to_lowercase` на каждую строку.
3. **Ввести seam `SearchBackend`** (`scan` / `index`), чтобы бэкенд менялся без переделки CLI.
4. **Гейт для индекса:** синтетический бенчмарк 1k / 10k / 100k сессий. Индекс включается, если p95 > 100 мс или корпус > 10k сессий / 1 ГБ.
5. **Выбор индекса после гейта:**
   - **SQLite FTS5 + trigram** — если нужен ранжированный подстрочный поиск по коду; учитывать C-сборку, размер индекса, миграции.
   - **Tantivy** — если нужен natural-language ranking, фасеты и корпус заметно больше.
   - Свой inverted index — только при доказанной необходимости.

## Реализация

Синтетический бенчмарк (1 000 сессий, 20 000 событий) на локальной машине: скан — 121 мс, FTS5 — 36 мс, построение индекса — 280 мс. Порог 100 мс превышен, поэтому FTS5 trigram реализован как **opt-in** (`sessions search --fts`, `sessions reindex`). Скан остаётся дефолтом; индекс не обновляется автоматически.

## Последствия

- В M4 индекс не добавляется; поиск остаётся сканом.
- Появляется измеримый критерий, когда FTS5/Tantivy оправданы, вместо преждевременной зависимости.
- Цена: на больших корпусах поиск будет медленнее до включения индекса; гейт это ловит.

## Альтернативы

- FTS5 сразу — отклонено: C-сборка, дублирование, rebuild и токенизация кода без доказанной потребности.
- Tantivy сразу — отклонено: тяжёлый граф зависимостей ради локальных сессий.
- Только `LIKE`/`GLOB` в SQLite — отклонено: тот же O(n) без выигрыша.
