# 030. Office: docx, xlsx, pptx

- **Статус:** Accepted
- **Дата:** 2026-11-13

## Контекст

Агенту нужны документы, таблицы и презентации, но тянуть LibreOffice/Python-стек в single-binary нельзя. Готовые Rust-крейты для pptx тянули уязвимые `quick-xml`/`zip`; это неприемлемо для security-пути.

## Решение

1. **docx:** чтение через `zip` + `quick-xml` (`word/document.xml`); создание — минимальный OOXML-пакет (Content Types, rels, document.xml) через `zip`.
2. **xlsx:** чтение через `calamine`, создание через `rust_xlsxwriter` (строковые ячейки, несколько листов).
3. **pptx:** встроенный шаблон `assets/default.pptx` (MIT, из `pptx` crate 0.1.0) как скелет мастеров/layout/theme; слайды и текст генерируются локально через `zip` + `quick-xml`. От самого `pptx` crate зависимость удалена — она тянула уязвимые `quick-xml 0.39` и `zip 7`.
4. **Инструменты:** `office_read`, `office_create_docx`, `office_create_xlsx`, `office_create_pptx`.
5. **Границы:** нет стилей/изображений/формул/диаграмм, нет редактирования существующих файлов; pptx-текст — один textbox на слайд.

## Последствия

- Нет внешних процессов и уязвимых транзитивных зависимостей.
- Форматирование минимально; для сложных документов нужен LibreOffice (отложено).
- OOXML-валидность проверяется нашими парсерами и структурой ZIP; офисный пакет не запускался.
- Office-файлы — недоверенный ввод: парсеры только читают; вывод ограничен tool output limit.

## Альтернативы

- `pptx`/`docx-rs` — отклонено: уязвимые `zip`/`quick-xml`.
- LibreOffice headless — отклонено: внешняя зависимость и тяжёлый образ.
- Полный OOXML-редактор — отложено: несоразмерно M7.
