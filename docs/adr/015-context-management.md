# 015. Промпт, AGENTS.md, skills и compaction

- **Статус:** Accepted
- **Дата:** 2026-11-12

## Контекст

Агенту нужен стабильный системный промпт, проектные инструкции, каталог навыков и способ не упираться в окно контекста. Всё это влияет на кэш провайдера и на воспроизводимость поведения.

## Решение

1. **Промпт собирается детерминированно** (`dshr-prompt`): identity → environment → tools → skills → project instructions → rules. Порядок и текст секций закреплены тестами.
2. **`AGENTS.md`** читается из `~/.dshr/AGENTS.md` и из каждого каталога от корня к `cwd` (root-first), с лимитами на файл и сумму. Отсутствие файлов не ошибка.
3. **Skills** (`dshr-skills`): discovery в `~/.dshr/skills` и `<cwd>/.dshr/skills`; в промпт попадает только каталог «имя + описание», тело `SKILL.md` загружается инструментом `skill` по требованию.
4. **Compaction** (`dshr-compaction`): при превышении порога оценивается размер; старые turn'ы суммируются отдельным вызовом модели, в журнал пишется событие `compaction` с `replaced_until_seq`. `derive_messages` отбрасывает события до cutoff, ставит summary первым и сохраняет последние turn'ы.
5. **Поиск** сейчас — линейный проход по журналам с сниппетами; SQLite FTS5 отложен, чтобы не тащить C-зависимость до появления реальных объёмов.

## Последствия

- Промпт стабилен и проверяем; изменение секций — видимая правка с тестом.
- Суммаризация стоит дополнительного вызова модели, но выполняется только при превышении порога.
- Compaction не переписывает журнал: история остаётся для аудита, меняется только проекция.
- Линейный поиск достаточен для сотен сессий; при росте — FTS5.

## Альтернативы

- Динамический промпт без фиксированного порядка — отклонено: ломает кэш и тесты.
- Полный `AGENTS.md` без лимитов — отклонено: риск раздуть контекст.
- Перезапись журнала при compaction — отклонено: теряется аудит.
