# Development

## Commands

```sh
cargo build -p dshr-cli
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
cargo deny check
cargo llvm-cov --workspace --summary-only
```

One command runs every gate exactly like CI:

```sh
scripts/check.sh          # everything (fmt, clippy, runtime assets, tests, evals, perf, browser)

Perf-бюджеты — wall-clock: `check.sh` печатает load, ждёт (до 180 с) его
падения ниже числа CPU и один раз повторяет прогон perf — на загруженном хосте
Spotlight/сборка/CI-соседство дают ложный красный, но реальная регрессия валит
оба прогона. Бюджет `event append (fsync on)` платформенный: 5 мс на Linux,
10 мс на macOS (APFS на занятом томе даёт p95 4–8 мс при прочих бюджетах с
>10x запасом; гейт всё ещё ловит 2x-регрессию — `crates/perf/tests/budgets.rs`).
scripts/check.sh quick    # fmt, clippy, workspace tests
```

## Web UI

The Leptos CSR app lives in `crates/web` and is excluded from the root workspace
(it targets `wasm32-unknown-unknown`). Build it with trunk:

```sh
rustup target add wasm32-unknown-unknown
cargo install trunk --locked        # or a prebuilt release binary
cd crates/web && trunk build --release
```

`crates/web/dist` is committed because `crates/server` embeds it via `include_bytes!`.
Rebuild the UI and commit `dist` whenever the frontend changes; `cargo test -p dshr-server`
checks that the wasm asset is served.

The Tauri shell (`crates/desktop`) is also outside the workspace, so Linux CI does not
need WebKitGTK. Build it with
`CARGO_TARGET_DIR=target cargo build --release --manifest-path crates/desktop/Cargo.toml`;
macOS CI runs its tests separately.

## CI

`.github/workflows/ci.yml` runs on macOS/Ubuntu/Windows: fmt, clippy, nextest, doc tests; separate `cargo-deny` and `coverage` jobs, plus `evals`, `perf` (release) and `web-e2e` (headless Chrome + client-half smoke) gates. The Linux test job also runs `scripts/check-runtime-assets.sh` (checksum gate for the vendored shared runtime). The experimental Windows AppContainer check is `continue-on-error`: it reports into the job summary but does not block trunk while the feature is deferred (see `docs/TECH-DEBT.md`). Failed nextest/clippy output is annotated and uploaded on failure.

`release.yml` builds tag releases (`v*`) for the three OSes.

## Tests

- Unit/integration tests: `cargo test`.
- Plugin host routes: `cargo test -p dshr-server --test plugins_live` — 16 checks: exact/prefix proxying, query/POST/preflight, 404 for unknown and reserved paths, route removal on stop, per-plugin `routes` in `GET /v1/plugins/status`, the MCP pseudo-tool filter (`list_resources`/`read_resource`/`list_prompts`/`get_prompt`), the loopback-only LAN policy (`403` unless `allow_plugin_routes_lan`), the C1.4 reference route rules (a duplicate exact route throws, a trailing-slash path is rejected), and the C1.1 internal session snapshot (`internal_session_snapshot_feeds_the_host_bridge`: usage fields, 401 on a wrong token, 404 when no internal token is configured).
- Client-half bridge: `cargo test -p dshr-cordis` — the bridge harness (102 checks: slot catalog/regions/slot mode, React mode and host-state, bridge services, the round-81 React contract, the round-89 C1.2 seat inject, generator `slots.inject` and generator `effect`, the round-91 C1.3 reference slot contract — undeclared/keyed/chain/duplicate throws, single shadowing, catalog standard kit, `ownerProps` and plain catalog values — and the round-92 C1.4 `configForms` contract: reference snapshot shape, stable identity between reads, `set` with a numeric revision fence and `unset`) plus assets, runtime, shared host runtime and manager tests.
- Reference slot catalog: `crates/cordis/src/slot-catalog.json` is a trimmed copy of the reference repository's generated `packages/extensions/cordis-client-runner/src/client/slot-catalog.ts` (`deepseek-ai/deepseek-harness` @ `39163dd`; the JSON `source` field records the repo@commit and path). dshr has **no local generator**: refresh it by re-trimming from a reference checkout when the reference is bumped, then re-run the harness — it checks the catalog metadata, maps every catalog key to one of the 17 regions and exercises the SlotCore registration rules the bridge derives from it.
- Reference host services (C1.4): `webServer` follows the reference `packages/host/webserver/src/index.ts` (independent exact/prefix tables, a duplicate `(kind, path)` throws `webserver: duplicate <kind> route`, an absolute pathname without trailing slash/query/hash, `getOrigin()`/`port`/`protocol` read the dshr server origin from the host bridge file, `registerFallback`/`registerUpgrade` throw explicitly as unsupported in the sidecar); `configForms` follows `packages/client/ui-settings/src/client/config-form-types.ts` (snapshot exactly `{status, value, base, user, revision: number, writable}`, `mutate(ops, expectedRevision?)` with atomic `set`/`unset` and a numeric revision fence, `set`/`unset` helpers); `ctx.baseUrl` mirrors the reference loader context (the `file://` URL of the plugin package root). The bridge harness checks the form contract and the server proxy test the route rules.
- Reference design-system primitives (C2.1–C2.5): `crates/server/assets/runtime/primitives.js` is ported from `deepseek-ai/deepseek-harness` @ `39163dd` (`packages/client/ui-primitives/src`), not an independent shim — atoms keep the reference DOM/ARIA/props/behaviour and styles use the `--dsw-alias-*` tokens with fallbacks; all 204 reference `Icon*` exports are generated from `icons/artwork.ts` (exact SVG paths, regular 1 / medium 1.3 strokes) and inlined instead of using the document sprite, with a Proxy fallback for future names. The smoke probe asserts the structural markers rather than only text, and the synthetic fixtures follow the reference contracts (`StateDot` `state: "done"`, `Tooltip` with an element child). The `Tooltip` is a full reference port since round 94 (C2.2): the label resolver evaluated on show, independent hover/focus triggers with `delayMs`/`focusDelayMs`, `openOnClick` pinning with outside-pointer/Escape/Tab dismissal, `onlyWhenClipped`, `maxWidth`, `portal`, `data-side`/`data-pinned`, nested suppression through context, `aria-describedby` while pinned, pointer modality (focus after a pointer never raises the bubble), touch hover excluded and a forward ref through the cloned anchor; `tooltip-placement.ts` (requested side → opposite → perpendicular, viewport clamp, overflow fallback), `input-modality.ts` and `ShortcutKeys` are ported as-is. `Menu`/`MenuItemButton` are a reference-core port since round 95 (C2.3), ported from `Menu.tsx`/`MenuRow.tsx`: data and component rows, separators/labels, `reserveIcon` columns (contextual), selection `check`/`fill`, `danger`/`current`, disabled-reason through the reference `Tooltip`, `shortcut` + `ShortcutKeys`, `children` rows and a `footer` group, aria (`menuitem`/`haspopup`/`expanded`/`disabled`/`describedby`/`keyshortcuts`/`current`), `dense`/`compact`, portal placement from the anchor rect (`minWidthFromAnchor`/`anchorPoint`/`align`/`side`) and the contextual attribute; keyboard walk (Arrow/Home/End with roving focus, Escape closes and returns focus via `focusWithoutRing`, Tab settles the row / Shift+Tab leaves, `autoFocus`), a one-level submenu on hover/ArrowRight that closes on ArrowLeft/Escape/selection, outside-pointer dismissal plus close-on-iframe-blur, and `closeOnPointerLeave` with a 200 ms pointer grace (`usePointerGrace`); `MenuItemButton`, `MENU_TRANSITION_MS`, `usePointerGrace`, `focusWithoutRing` and `isMobileDevice` are exported. Round 96 (C2.4) closes the rest of the reference `Menu`: submenu placement follows `menu-submenu-position.ts` (a side child card when either side of the parent card fits, otherwise the single-page layout where child rows replace the parent page behind a non-selecting back row — `data-menu-back`, chevron-left, `submenuBackLabel` or the parent label — plus a separator; Escape/ArrowLeft return to the parent page with focus on the parent row), the focus contract (hover opens the submenu without stealing focus, ArrowRight/click focus the first child row), the 200 ms hover grace between the parent and child cards (entering the child cancels the close via `cancelSubmenuClose`) and `MenuGroup` + `observeStickyMenuGroups` ported from `MenuGroup.tsx` (`section[role=group]` with `aria-labelledby`, `data-menu-group`/`data-menu-group-start`/`data-menu-group-heading` attributes and sticky headings driven by a `data-stuck` IntersectionObserver/ResizeObserver pair). Partials: only the detailed `useMenuSubmenu` focus-transition/page-anchor mechanics stay simplified (our own CSS/JS placement). Round 97 (C2.5) ports the reference `JsonBlock` from `markdown/JsonBlock.tsx` (collapsible ▾/▸, `label`/`payload`/`defaultOpen`/`truncatedLabel`, a 20,000-character cap with a truncated footer and a safe `JSON.stringify` fallback) and replaces the simplified `MarkdownText` with an API-compatible dependency-free GFM subset while keeping the reference prop surface (`text`/`streaming`/`labels`/`fileMentions`/`pathImages`/`variant`/`omitHtml`/`textInteractionSource`): headings 1–6, paragraphs, ul/ol, fenced code, blockquotes, hr, inline code/bold/italic/strike, links and images restricted to `http(s)`/`mailto` (unsafe protocols — `javascript:`/`data:` — are dropped and relative images are not rendered), raw HTML rendered as nothing and the `variant="compact"` data attributes — the upstream micromark/mdast, shiki highlighting, KaTeX, footnotes and incremental streaming are not bundled. Store seats/renderer, chain dispatch/hoc nesting and ownerProps from real shell sites remain C-full. The shared runtime artifact is 424,801 bytes; verify the bytes with `scripts/check-runtime-assets.sh`.
- Ignored/live: DeepSeek smoke, Chrome CUA, search benchmark.
- Eval suite and perf budgets are separate CI jobs; the eval report is uploaded as an artifact.

## Layout

See README “Структура”. New crates are `dshr-*` and added to the root `[workspace] members`; Windows-only vendored code lives under `vendor/` and is excluded from the workspace.

## Debugging

- `dshr doctor` — config/provider/tool checks.
- `RUST_LOG=debug` — JSON logs to stderr.
- `OTEL_EXPORTER_OTLP_ENDPOINT=...` — OTLP traces.
- `DSHR_WINDOWS_SANDBOX=1` — experimental AppContainer (fail-closed by default).
